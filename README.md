# Telegram ID Widget

**Человек вводит Telegram username на сайте — скрипт находит числовой ID аккаунта и добавляет его к заявке.**

Для обычных HTML-форм и GetCourse. Можно подключать к разным сайтам: регистрировать каждый домен не нужно. Посетителю не требуется входить в Telegram или запускать бота.

В проекте нет общих ключей или готового чужого сервера. Вы устанавливаете свою копию и вводите реквизиты своего отдельного бота.

```text
Форма на вашем сайте → ваш сервер → Telegram
                            ↓
                   ID в поле заявки
```

Если человек сразу нажал «Отправить», форма дождётся поиска. При изменении username прежний ID очищается. Это поиск указанного аккаунта, а не подтверждение владения им: человек может указать чужой username.

## Что понадобится

| Что | Где взять |
|---|---|
| Новый отдельный Telegram-бот | Бесплатно создать через @BotFather |
| `api_id` и `api_hash` | Получить на my.telegram.org |
| VPS с Ubuntu 24.04 LTS | Заказать у хостинга |
| Домен или поддомен | Добавить в панели управления доменом |
| Email | Ваш рабочий email для HTTPS-сертификата |

VPS — арендованный компьютер, который работает круглосуточно. Обычный хостинг только для HTML/PHP может не подойти. Практический ориентир для небольшого сервиса: 1 процессор и 1–2 ГБ памяти; скорость зависит также от лимитов Telegram.

**Простой путь ниже рассчитан на отдельный сервер Ubuntu 22.04/24.04, где порты 80 и 443 ещё не заняты сайтами.** Мастер не отключает чужие сайты. Для сервера с существующим Nginx/Caddy есть [расширенная инструкция](docs/advanced.md).

## Шаг 1. Создайте бота

1. В Telegram найдите официальный **@BotFather**.
2. Отправьте `/newbot`.
3. Укажите название, например `Form Lookup`.
4. Придумайте свободный username, заканчивающийся на `bot`.
5. Сохраните **токен** — длинную строку с двоеточием, которую выдаст BotFather.

Создайте именно нового бота. Не используйте основного бота SaleBot, BotHelp или другого сервиса. Добавлять нового бота в группы и подключать к конструктору не требуется.

При запуске программа проверяет webhook и отказывается входить в бота, если события уже направляются другому сервису. Подключения через polling эта проверка не обнаруживает, поэтому отдельный бот всё равно нужен.

## Шаг 2. Получите реквизиты приложения

1. Откройте [my.telegram.org](https://my.telegram.org) под аккаунтом владельца проекта.
2. Войдите по номеру телефона и откройте **API development tools / Инструменты разработки API**.
3. Создайте приложение. Название — `Form Lookup`, короткое имя — `formlookup`. Если есть выбор платформы, укажите «Бот / сервер» или подходящий серверный вариант. URL можно оставить пустым, если форма позволяет.
4. Сохраните появившиеся **`api_id`** и **`api_hash`**.

Это реквизиты приложения. Сервис входит **по токену бота**, а не в вашу личную переписку. Установщик не запрашивает номер телефона, код Telegram и пароль от аккаунта.

## Шаг 3. Подготовьте адрес сервиса

В панели управления доменом добавьте DNS-запись:

| Поле | Что указать |
|---|---|
| Тип | `A` |
| Имя / хост | Например, `lookup` |
| Значение | Публичный IPv4 вашего VPS из кабинета хостинга |

Получится адрес вида `lookup.example.com`. Ваша запись должна вести на **ваш** сервер. Если для этого имени есть AAAA-запись, она тоже должна вести туда; ошибочную лишнюю запись уберите.

Обновление DNS занимает некоторое время. Если у провайдера DNS есть режим прокси, для первой установки используйте обычную DNS-запись без проксирования. Порты **80/TCP и 443/TCP** должны быть открыты в панели хостинга и firewall. Мастер сам firewall не меняет.

## Шаг 4. Установите сервис

Откройте **консоль / терминал сервера** в кабинете хостинга. Если её нет, подключитесь по SSH по инструкции хостинга. Команды выполняются на VPS, а не в консоли браузера сайта.

Вставьте команды по очереди:

```bash
sudo apt-get update
sudo apt-get install -y git
git clone https://github.com/vihlyanec/telegram-id-widget.git
cd telegram-id-widget
sudo bash install.sh
```

Мастер задаст пять вопросов:

1. Ваш домен сервиса — **без** `https://` и слеша в конце.
2. Email.
3. `api_id`.
4. `api_hash`.
5. Токен нового бота.

При вводе секретов символы не отображаются — это нормально. Вставьте значение и нажмите Enter, без кавычек и подписей вроде `api_hash=`.

Мастер при необходимости установит Docker из официального репозитория, сохранит `.env`, соберёт приложение и запустит его. Caddy автоматически получит HTTPS-сертификат и будет его продлевать. Первая сборка может занять несколько минут — не закрывайте терминал.

Если Docker уже установлен, мастер использует его, не переустанавливая. Если `.env` уже есть, предложит использовать сохранённые настройки.

### Проверка результата

Откройте `https://ВАШ-ДОМЕН/demo.html`. Введите существующий username **человека** и нажмите кнопку: должен появиться числовой ID. Канал, группа или бот для этой проверки не подходят.

По адресу `https://ВАШ-ДОМЕН/health` исправный сервис отвечает `{"ok":true}`. Если установщик сообщает, что HTTPS ещё не подтверждён, установка не объявляется полностью готовой: проверьте DNS и порты по таблице ниже.

## Шаг 5. Подключите форму

`ВАШ-ДОМЕН` ниже — домен сервиса из шага 3. Сайт с формой может находиться на другом домене.

### Обычный сайт

```html
<form action="/your-form-handler" method="post">
  <label>
    Ваш Telegram
    <input name="telegram_username" placeholder="@username" required>
  </label>
  <input type="hidden" name="telegram_id">
  <button type="submit">Отправить</button>
</form>

<script src="https://ВАШ-ДОМЕН/widget.js" defer></script>
```

Замените `/your-form-handler` своим обработчиком заявки. Скрипт добавляет ID, а отправку письма или запись в CRM выполняет ваш обычный обработчик. Если названия полей другие, укажите их в настройках: [подробная инструкция](docs/integration.md).

### GetCourse

1. В дополнительных полях **пользователя** создайте два текстовых поля: «Telegram username» и «Telegram ID».
2. Добавьте оба в одну форму как штатные поля пользователя. Username можно сделать обязательным. ID средствами GetCourse обязательным не делайте: его заполнение контролирует скрипт.
3. Укажите скрипту эти два поля через CSS-селекторы — адреса элементов в разметке.
4. Спрячьте обёртку поля ID через CSS. Само поле оставьте в форме и не ставьте `disabled`.
5. Вставьте [шаблон getcourse-snippet.html](getcourse-snippet.html) в HTML-блок, заменив домен и селекторы.
6. Отправьте тестовую заявку и проверьте ID в карточке пользователя.

Шаблон предполагает классы `tg-username` и `tg-id` на обёртках соответствующих полей. Если редактор позволяет задавать CSS-класс, назначьте их. Если такой настройки нет, реальные селекторы нужно взять из опубликованной формы — здесь может потребоваться помощь специалиста. Единого имени поля для всех аккаунтов GetCourse нет.

**Произвольный скрытый input сам по себе не создаёт поле GetCourse.** Используйте штатное дополнительное поле. Конкретную форму нужно проверить после подключения: обработчики конструкторов различаются.

## Если что-то не работает

| Что произошло | Что делать |
|---|---|
| «Порты 80/443 уже заняты» | Не отключайте чужие сайты. Используйте отдельный VPS или [существующий прокси](docs/advanced.md). |
| Нет сайта или HTTPS | Проверьте A/AAAA, обновление DNS и открытые 80/443. |
| «Аккаунт не найден» | Проверьте написание. Допустимы `@username` и `t.me/username`. |
| «Это канал или группа» / «Укажите аккаунт человека» | Для поиска нужен личный аккаунт, а не канал или бот. |
| «Бот уже подключён через webhook» | Создайте нового технического бота. Проект не удаляет webhook автоматически. |
| «Telegram временно ограничил поиск» | Подождите. Программа соблюдает паузу Telegram. Перезапуск не является решением лимита. |
| В демо ID есть, в GetCourse нет | Проверьте селектор ID и штатное поле в той же форме. |
| При клике ничего не происходит | Проверьте загрузку `widget.js`, селекторы и [особенности кнопок](docs/integration.md). |
| Форма внутри чужого iframe | Установите скрипт внутри самой формы. Код снаружи не может читать cross-origin iframe. |

Состояние и сообщения сервиса:

```bash
cd telegram-id-widget
sudo docker compose ps
sudo docker compose logs --tail 50 lookup caddy
```

Не публикуйте `.env`, токен, `api_hash` и сессию бота в вопросах или GitHub Issues. Перед отправкой журналов проверьте их содержимое.

## Обновление и остановка

```bash
cd telegram-id-widget
git pull --ff-only
sudo docker compose up -d --build
```

Настройки и Docker-тома сохранятся. Не используйте `docker compose down -v` для обновления: флаг `-v` удаляет данные сессии и сертификатов.

Остановить, сохранив данные: `sudo docker compose stop`.

Запустить снова: `sudo docker compose up -d`.

Для резервного копирования сохраните `.env` и тома `telegram_session`, `caddy_data`, `caddy_config` средствами хостинга. Это приватные данные — в GitHub они не нужны.

## Ограничения

- ID из скрытого поля можно изменить вручную. Для авторизации или выдачи доступа нужны отдельная серверная проверка и Telegram Login.
- Поиск не подписывает человека на основного бота и не создаёт клиента в SaleBot/CRM.
- Username может измениться; успешные ответы кешируются на 5 минут.
- Telegram ограничивает запросы. Есть очередь, интервал и обработка FLOOD_WAIT; массовый поиск не гарантируется.
- API по умолчанию открыт любым сайтам. CORS не является авторизацией. Для заметного трафика нужны наблюдение и ограничения на хостинге.

## Для разработчиков

Node.js 22+, `npm ci`, `cp .env.example .env`, заполнить реквизиты, `npm start`. Без прокси оставьте `TRUST_PROXY_HOPS=0`; контейнерная схема с Caddy задаёт 1.

```bash
npm ci
npm test
```

Тесты не используют настоящие ключи и не обращаются к Telegram. Они проверяют API, лимиты, очередь, очистку ID, гонки и отправку форм. [Архитектура и ручной запуск](docs/advanced.md).

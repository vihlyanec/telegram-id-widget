# Ручной запуск и существующий прокси

## Архитектура

- `public/widget.js` — браузерный скрипт без Telegram-секретов.
- `app.cjs` — HTTP API и раздача демо/скрипта, CORS и IP-лимит.
- `lookup.cjs` — нормализация username, очередь, кеш, FLOOD_WAIT.
- `server.cjs` — бот через teleproto/MTProto, сохранение сессии.
- `install.sh` — мастер для Ubuntu; `compose.yaml` — приложение и Caddy.

Один экземпляр сервиса: очередь и кеш хранятся в памяти. Успех кешируется 5 минут,
общий интервал между Telegram-запросами — 3 секунды, очередь ограничена.
Интервал — настройка проекта, а не обещание лимита Telegram. Соблюдайте FLOOD_WAIT.
Username не доказывает владение аккаунтом. ID хранится строкой.

## Если уже есть Nginx или другой HTTPS-прокси

Не запускайте стандартный compose.yaml поверх занятых 80/443. Используйте
`compose.proxy.yaml`: он поднимает только приложение на localhost:3008.

```sh
cp .env.example .env
# Заполните TG_API_ID, TG_API_HASH, TG_BOT_TOKEN.
chmod 600 .env
sudo docker compose -f compose.proxy.yaml up -d --build
```

Пример location внутри отдельного HTTPS-vhost вашего Nginx:

```nginx
location / {
    proxy_pass http://127.0.0.1:3008;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 45s;
}
```

Домен, TLS-сертификат и проверку/reload конфигурации настройте обычным способом
для своего сервера. Это пример, а не команда замены существующего конфига.
Все дальнейшие compose-команды для этой схемы выполняются с `-f compose.proxy.yaml`.

TRUST_PROXY_HOPS=1 подходит при ровно одном доверенном прокси и недоступном извне
Node.js upstream. Не завышайте число доверенных прокси и не открывайте upstream
в интернет: иначе клиент сможет подделывать IP для обхода ограничения.

## Запуск без Docker

Нужен Node.js 22+. На Linux/macOS:

```sh
npm ci
cp .env.example .env
# Заполните TG_API_ID, TG_API_HASH, TG_BOT_TOKEN; остальные поля по необходимости.
chmod 600 .env
npm start
```

При прямом доступе без прокси оставьте HOST=127.0.0.1 и TRUST_PROXY_HOPS=0.
Откройте http://localhost:3000/demo.html на той же машине. Для публичного сайта
нужен HTTPS-прокси и постоянный процесс (например, systemd).
Сохраните каталог data между перезапусками.

## Настройки

| Переменная | Значение |
|---|---|
| TG_API_ID / TG_API_HASH | Реквизиты приложения владельца установки |
| TG_BOT_TOKEN | Токен отдельного нового бота |
| ALLOWED_ORIGINS | `*` для всех сайтов либо точные origins через запятую, без конечного `/` |
| APP_DOMAIN / ACME_EMAIL | Для Caddy в стандартной Docker-схеме |
| HOST / PORT | Адрес и порт Node.js; в Compose переопределяются |
| SESSION_FILE | Файл сессии; в Docker хранится в отдельном томе |
| TRUST_PROXY_HOPS | Количество доверенных прокси; 0 без прокси, 1 в предлагаемых схемах |

Токен, api_hash, .env и сессия приватны. Не размещайте весь каталог проекта как
статические файлы. API отдаёт только явно предусмотренные маршруты.
Отзыв токена не следует считать единственной мерой при утечке MTProto-сессии.

## Ошибки и ограничения

API: POST `/api/telegram-id`, JSON `{"username":"name"}`.
Успех: `{"username":"name","telegram_id":"123"}`.
Ошибка: HTTP 400/404/422/429/503 с code и error. Для общей паузы может быть Retry-After.
Не вызываются getUpdates, setWebhook, deleteWebhook и отправка сообщений.

CORS ограничивает браузеры, но не авторизует запросы: Origin можно подделать
вне браузера. Для открытой эксплуатации добавьте WAF/лимиты своего хостинга,
наблюдение за нагрузкой и повторную серверную проверку полей, где это необходимо.
Не сохраняйте тела запросов и секреты в журналах прокси.

## Docker и лицензии зависимостей

Мастер устанавливает Docker по официальной apt-инструкции и не удаляет конфликтующие
пакеты. Если Docker есть без Compose plugin, установите плагин способом,
подходящим вашей установке: https://docs.docker.com/compose/install/linux/.

Исходный код проекта распространяется под MIT. Docker, Caddy и npm-зависимости
имеют собственные лицензии; они не заменяются лицензией этого репозитория.

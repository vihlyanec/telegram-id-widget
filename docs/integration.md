# Подключение к формам

## Одно подключение на страницу

Замените `lookup.example.com` на адрес **своего** сервиса:

```html
<script src="https://lookup.example.com/widget.js" defer></script>
```

По умолчанию скрипт ищет `input[name="telegram_username"]` и скрытое поле
`name="telegram_id"` в той же форме. Если скрытого поля нет, создаёт его.
Можно вводить `username`, `@username`, `t.me/username` или `https://t.me/username`.
Поиск начинается при выходе из поля; запрос на каждый символ не отправляется.

## Другие поля

```html
<script
  src="https://lookup.example.com/widget.js"
  data-username-selector='input[name="YOUR_USERNAME_FIELD"]'
  data-id-selector='input[name="YOUR_ID_FIELD"]'
  data-required="true"
  defer
></script>
```

Селектор — способ найти элемент страницы. Например, `[name="telegram"]` означает
элемент с HTML-атрибутом `name="telegram"`, а `.tg-username input` — input внутри
обёртки с классом `tg-username`. Это не обязательно видимое название поля.

При `data-id-selector` скрипт использует только существующее поле. Он не подменяет
его произвольным input. Оба поля должны быть в одном `form`. Настройка формы
подключается, когда оба поля появились; ошибки селекторов нужно проверить до
публикации. На странице может быть несколько форм, в том числе добавляемых позже.
В каждой форме должно быть одно подключаемое поле username и одно поле ID.

## GetCourse

Используйте штатные дополнительные поля пользователя. Шаблон:
[getcourse-snippet.html](../getcourse-snippet.html).

Назначьте обёртке username класс `tg-username`, обёртке ID — `tg-id`, если редактор
позволяет задавать CSS-классы. Иначе замените селекторы реальными значениями из
опубликованной формы. Не переименовывайте штатные атрибуты `name` GetCourse.

Скрывайте обёртку ID через `display:none`, оставляя input включённым.
Не делайте поле ID обязательным через редактор. Существующие обработчики CRM,
оплаты и переадресации остаются штатными — обязательно проверьте их тестовой заявкой.

## Кнопки и отправка

По умолчанию распознаются button[type=submit], input[type=submit], button без type
и элементы с `data-tgid-submit`. Для нестандартной кнопки добавьте:

```html
data-submit-selector=".my-send-button"
```

Обязательный режим (`data-required="true"`, по умолчанию) блокирует отправку,
пока ID не найден. Поэтому недоступность сервиса временно блокирует заявку.
`data-required="false"` позволяет отправить заявку с пустым ID, если поиск не готов.

Проверяются click и submit. Чужой код, который сам отправляет запрос или вызывает
`form.submit()` в обход событий до нашего обработчика, может потребовать адаптации.
Формы внутри стороннего cross-origin iframe недоступны родительскому скрипту:
устанавливайте код внутри документа самой формы.

## События

При записи ID срабатывают `input` и `change`. Поле username также посылает событие
`tgid:change` с `detail.state`: idle, loading, success, invalid, error.
В detail есть telegram_id, а при успехе — username.

## Проверка после подключения

1. Найдите аккаунт человека и отправьте заявку одним кликом.
2. Убедитесь, что ID сохранён в нужном поле карточки, а не просто появился на странице.
3. Измените username: старый ID должен исчезнуть.
4. Проверьте ошибочный username, канал, новую и существующую учётную запись.
5. Проверьте мобильную версию, popup, оплату и редирект, если они используются.

Скрытое поле не является подтверждением личности. Для действий, где нужна
достоверность, проверяйте данные на своём сервере и используйте Telegram Login.
